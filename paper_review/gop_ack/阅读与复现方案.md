## 2. 论文内核与对当前工作的价值

对象：不同无线技术之间的数据反馈。问题：已有 CTC 数据通道缺乏可靠而简短的 ACK，采样时刻偏移会破坏检测。方法：把 ACK 编成重复的 offset-resistant signals（ORS），使重复波形周期等于接收机计算相位差的时间间隔。

核心条件是 w(t+T)=w(t)，因此理想信道下，对任意处于有效重复区间的 t，angle(w(t+T)·conj(w(t)))=0。波形周期与相位差间隔不一致时，可按两端基本时间单位的公倍数匹配。

当前项目已能 BLE→802.15.4 传输载荷，最直接的延伸是增加反向 802.15.4/OQPSK→BLE 物理层 ACK。它比继续单独添加不同协议的自收发更贴近 CTC 的核心问题：异构设备如何确认彼此收到数据。

注意：论文的 ACK chip 序列位于 OQPSK 调制器输入处，绕过常规符号到 DSSS 码片的映射。例如 10101 等特殊 chip 序列不是让普通 Zigbee 发送 API 发送同名字符串。复用的应是 half-sine 脉冲与 OQPSK 调制过程，而不是现有 build_mac→modulate_symbols 的完整标准帧生成链。

现有可复用代码：

- `ctc_lab/ieee802154.py`：半正弦脉冲、I/Q 错开半个脉冲的调制基础。
- `ctc_lab/ble_receiver.py` 与 `msk_receiver.py`：复数相位差的计算方式。ORS ACK 需要单独检测器，不走 BLE 地址/CRC 检查。
- `ctc_lab/channel.py`：噪声、分数采样延迟、频偏和时钟误差。
- `send_receive.py`：限时 RF、先停止发射再离线解析、原始 IQ 与报告保存。

## 3. 推荐先复现的 Zigbee→BLE ORS

按作者稿 §IV、表 I、图 7–8：

- BLE 接收机相位差间隔为 1 μs；波形应每 1 μs 重复。
- 一个 2 μs 的 ORS 由两个 1 μs 重复段组成。连续构造 M 个重叠 ORS，仅需 M+1 个重复段。
- 原始序列长度为 2M+3 个 chip，其中奇数位置固定为 bI，偶数位置固定为 bQ。
- 通过能量门限、满足相位差门限的数量、ACK 类型投票进行判决。
- 四个 (bI,bQ) 组合 (1,1)、(0,1)、(0,0)、(1,0) 对应四类 ACK；该类型判决依赖 I/Q 相位参考。

作者稿模型验证给出 M=15、相位差门限 1 rad、检测数量严格大于 8；能量门限 0.013 mW。当前 IQ 是 ADC 计数或归一化数值，不能直接把 0.013 mW 当作同单位阈值，需标定或噪声归一化，并报告转换方法。

## 4. 已完成的初步机制检查

脚本：`ors_probe.py`；结果：`ors_probe_results.json`。

这是从原始 chip 构造半正弦 OQPSK 的独立、无噪声机制检查。使用 64 MSPS、M=15、每个波形 64 个采样偏移位置、四种 ACK，共 256 个测试；检测器只接收样本，不读取发送类型。测试窗口预先给定，尚未实现盲检测、信道补偿或 RF。

| 条件 | 检测到 ACK | ACK 类型正确 | 含义 |
|---|---:|---:|---|
| 相位参考一致、无频偏 | 256/256 | 256/256 | 重复波形及理想类型判决可重建 |
| 整体旋转 90° | 256/256 | 0/256 | 相位差检测不受固定旋转影响，但象限类型会变 |
| 加 25 kHz 频偏 | 256/256 | 52/256 | 检测门限内，类型仍可能因随时间旋转而错 |
| 加 200 kHz 频偏 | 0/256 | 0/256 | 此设置下相位差超过 1 rad 门限 |

这里的能量阈值为归一化 0.1，并非论文的 mW 阈值。以上数字不代表论文性能曲线复现，更不代表空口成功率。90° 实验用于确认我们复现时必须解决的前置条件；不能仅据此断言论文错误，论文实现可能复用前置载波恢复，而其完整细节尚需确认。

频偏会在间隔 T 上额外产生 wrap(2πΔfT) 的相位差。需要将采样位置偏移、采样时钟偏差、频偏和固定载波相位分别测试，不应统称“offset”。

## 5. 现有硬件下的复现层级

| 层级 | 当前可行性 | 能证明什么 / 仍缺什么 |
|---|---|---|
| ORS 波形与相位差机制 | 高；已做初步检查 | 可继续扩展随机噪声和边界条件；不代表实测 |
| Zigbee→BLE ACK 同板 RF | 高；待实现专用检测器 | 板卡发 OQPSK ORS、收 IQ，电脑运行 BLE 间隔的相位差检测。没有独立 BLE 芯片互通证据 |
| 数据接收→ACK→超时重传闭环 | 中；先用宽松时序 | 两个逻辑节点需因真实解码结果触发 ACK，而不是提前拼好整段波形 |
| 论文式 192 μs SIFS | 目前不能保证 | 现有 Python、USB、离线解析链不能证明该实时截止时间；需要板端实时收发控制 |
| 双独立节点距离曲线 | 当前设备不足 | 同板双通道仍可能共用时钟/本振且存在耦合；距离、独立振荡器和终端互通需要额外独立硬件 |
| 手机直接确认 ORS ACK | 普通扫描接口不适用 | 手机 BLE 扫描输出标准包，不提供 ORS 检测所需的原始 IQ/相位差；ORS 也未必是有效 BLE 广播 |
| Zigbee→Wi-Fi ACK | 核心算法可先离线复现 | 使用 Wi-Fi 接收机的延迟相位差/相关机制，不必先实现完整 Wi-Fi 包解码；精确对照还需重建论文采样及滤波链 |

板卡是当前已检测到的 PlutoSDR Rev.C / AD9361 类设备，不等同于原论文的两台 Y590 SDR。可复现算法和受控 RF 原理，但不能声称硬件条件完全一致。

## 6. 原论文参数、比较基线与待澄清项

作者稿 §VI.A 与 Wireless Communications 实验：两台 Y590，GNU Radio 3.8，Zigbee ch18 与 Wi-Fi ch6，标称信道中心相差 3 MHz；每次实验发送 10000 个 ACK，间隔 0.02 s，标称功率 −1.4 dBm，距离范围文字描述为 0.5–8 m。这些数据不能直接套用 AD9361 增益数值；增益设置不是经标定的空口发射功率。

作者稿的 GOP-ACK 实验设置为 M=7、相位门限 0.8 rad、数量门限 4。Wireless Communications 文章明确 32 μs 总时长、640 样本、相位门限 0.25π、数量门限 4，强调各方法相同时间与采样开销。主稿基线描述包含正负相位投票，杂志文章包含绝对相位门限的检测规则，必须分版本实现。

Wi-Fi 相位差基本间隔为 0.8 μs，ORS 采用 4 μs 波形，并通过 1/5 降采样匹配 4 μs 比较间隔。3 MHz 信道间隔在 4 μs 上对应整数周相位积累，不应将该特定设置等同于对任意频偏免疫。

补充材料第 14 页确有参数疑点：正文写 M=3，而检测数量门限为 10；按主稿 N_ORS≤M 的定义不能同时直接成立。可能涉及定义或排版问题，当前不能擅自替作者选择参数。补充材料一些 SNR 趋势的文字描述也与常规解释及图意存在疑点，应以实际公式、图和单位逐项核对。

缺失或需确认：

1. 原始 GNU Radio 工程、MATLAB 仿真代码、种子、IQ 和距离曲线原始数值。
2. 四类 ACK 的载波初始相位参考、频偏估计和补偿如何实现。
3. 所有能量门限对应的功率定义、归一化、增益与接收滤波器。
4. 候选 ACK 窗口如何确定；盲检测的误警率、噪声/其他协议下拒检能力。
5. 稀有采样边界、时钟 ppm、独立本振和多径条件的处理。
6. 门限“>4”还是“≥4”的确切实现，以及补充材料 M 与门限的冲突。
7. 标准 ACK 时序如何落地，与电脑调度、USB 缓冲时延是否分开计算。

## 7. 实施顺序与验收指标

第一步：只做 ACK 有无检测。生成原始 OQPSK ORS，与现有 BLE→802.15.4 数据链分开；建立真实盲窗口搜索、能量门限、延迟相位差和重复段投票。先不把四象限类型作为可靠反馈。

第二步：蒙特卡洛仿真。独立扫描采样位置 −0.5～0.5 μs、SNR、频偏、固定相位 0～2π、时钟 ppm。训练/校准门限与验证数据分开。报告漏检率、误警率、类型混淆矩阵和置信区间；把纯噪声、普通 BLE、标准 802.15.4 和 ESB 作为负样本。

第三步：限时同板 RF。保留独立采集块及 IQ；检测器不读取发送类型、时刻或 manifest。先验证 ACK 存在性，再测试带独立参考的 ACK 类型。共享时钟下仍应数字注入频偏与随机相位，避免把共本振优势误认为普遍性能。

第四步：真实触发闭环。只有目标数据 FCS 通过才产生 ACK；发送端只依据接收到的 ACK 决定完成或超时重传。允许丢 ACK、错 ACK、重复包并记录序号。初期用宽松时序，明确不是标准 192 μs SIFS。

第五步：独立第二节点与原论文图表对照。原始数据补齐后再严格重建等开销的 symbol-level、bit-level 和 ORS 基线，固定同一采集、功率及统计规则。没有精确重建基线时，只能称机制对照，不能声称复现或超越原论文。

闭环指标：唯一有效载荷字节数 / 实测总用时、平均和尾部时延、重传次数、ACK 误警及漏检、各层成功率。循环发送/分块采集的当前历史帧数不能直接换算 PRR 或净吞吐量。

可探索的后续方向：在统一虚警约束下的噪声自适应门限、带相位参考的多类 ACK、频偏补偿、ESB→802.15.4/反向 ACK 的可行性分析。它们是待验证设想，不能仅因加入现有项目就认定具有论文创新性。

结论：最值得推进的是“现有 BLE→802.15.4 数据 + 反向 ORS ACK”的分层复现。现有设备足够完成核心仿真与同板 RF 原理验证；独立终端互通、原论文距离曲线和严格实时 ACK 仍有明确缺口。
